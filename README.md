# ВОнлайне (ВО)

Социальная сеть для локальной сети: оформление как у социальных сетей конца нулевых —
узкая колонка по центру, Tahoma 11px, белые блоки с тонкой рамкой, анкета таблицей
и стена внизу страницы. Начинка при этом современная: вложения всех типов, голосовые
сообщения, групповые беседы, уведомления, настройки приватности — и нормальная
раскладка на телефоне, где колонка становится одной, а меню — лентой под шапкой.

Обычные страницы, которые отдаёт сервер. Никакого SPA, никаких сборщиков.

## Что умеет

| Раздел | Что внутри |
|---|---|
| Страница | аватар, статус, анкета, счётчики, короткий адрес вида `/ivan`, статус «в сети» |
| Записи | до 10 вложений (фото, видео, музыка, документы), «Мне нравится», комментарии с ответами, редактирование, удаление, закрепление, репосты, `@упоминания` и `#хештеги` |
| Сообщения | личные диалоги и групповые беседы, вложения, **голосовые сообщения**, «печатает…», мгновенная доставка, правка и удаление своих сообщений, поиск по переписке |
| Ответы | лайки, комментарии, упоминания, репосты, заявки и приглашения в беседы — со счётчиком |
| Друзья | заявки входящие и исходящие, общие друзья, кто сейчас в сети |
| Фотографии | альбомы, загрузка пачкой, просмотр с листанием, лайки, комментарии, выбор аватара |
| Видеозаписи | MP4 и WebM со встроенным плеером, обложка и длительность при наличии ffmpeg |
| Аудиозаписи | свои файлы с плеером, разбор имени на исполнителя и название |
| Документы | PDF, архивы, текст; скачиваются под исходным именем |
| Группы | создание, аватар, участники, стена с вложениями, права создателя |
| Новости | лента записей друзей и групп |
| Поиск | по людям, записям и группам |
| Приватность | кто видит страницу, фотографии, аудио и друзей; кто пишет на стену и в сообщения; чёрный список |
| Настройки | вся анкета, смена пароля с завершением прочих сеансов, удаление страницы |
| Вход | обычный логин с паролем или единый аккаунт сети RetroCore одной кнопкой |

Мелочи в духе эпохи: даты «сегодня в 14:03» и «12 мар в 9:15», склонения («3 друга», «5 друзей»),
«был / была на сайте», Ctrl+Enter отправляет форму.

## Оформление

Внешний вид собран по образцу старого ВКонтакте: узкая колонка ~800px по центру,
синяя полоса шапки ровно над контентом (а не во всю ширину экрана), белый фон вокруг,
Tahoma 11px, серая полоса с названием страницы и состоянием справа.

Значок в правом верхнем углу переключает оформление по кругу — **☀ светлая → ☾ тёмная →
✦ неоновая**. У вошедшего выбор хранится в его настройках, у гостя — в сессии.
Ещё две темы выбираются в настройках:

| Тема | Что это |
|---|---|
| `vo` | оригинал: тот самый старый ВК, тема по умолчанию |
| `dark` | он же в тёмных тонах, без свечения |
| `neon` | тёмная со свечением и **настраиваемыми цветами** |
| `fresh` | светлая с современной подачей: системный шрифт, скругления, мягкие тени |
| `modern` | карточки, колонка пошире, липкое меню |

### Свои цвета для неоновой темы

В «Мои Настройки» → «Оформление» задаются два акцента и фон. Вся остальная палитра
(подсветка, рамки, кнопки, ссылки, панели) считается из них через `color-mix`, поэтому
хватает трёх значений. Есть готовые наборы: Киберпанк, Кислота, Закат, Лёд, Матрица.
При выборе цвета страница перекрашивается сразу, без сохранения.

Заглушка вместо аватара в тёмной и неоновой темах не картинка, а силуэт, собранный
из градиентов на тех же переменных, — поэтому он перекрашивается вместе с остальным
и не выбивается из палитры.

Цвета принимаются строго в виде `#rrggbb` — они попадают в разметку отдельным
`<style>`, поэтому всё, что не проходит проверку, заменяется значением по умолчанию.

Все темы — отдельные самодостаточные файлы в `public/css/`, разметка у них общая.

### На телефоне и планшете

Разметка одна и та же, меняется только раскладка — за это отвечает общий файл
`public/css/mobile.css`, он подключается после темы и работает во всех оформлениях.

| Ширина | Что происходит |
|---|---|
| до 920px | колонка перестаёт быть фиксированной и тянется по экрану |
| до 700px | одна колонка: левое меню превращается в прокручиваемую ленту под шапкой, шапка липкая, поиск на всю ширину, анкета и формы идут подписью над полем, плитки фотографий — сеткой по всей ширине |
| до 400px | аватар и плитки мельче |
| экран боком | липкая шапка отключается, чтобы не занимать половину высоты |

Мелочи: поля ввода от 16px — иначе Safari зумит страницу при фокусе; цели для пальца
не ниже 32–38px; лента меню сама подкручивается к текущему пункту; цвет адресной
строки браузера берётся из темы.

## Быстрый старт

**Windows:** двойной клик по `start.bat` — он сам поставит зависимости, заведёт
демо-страницы и откроет сайт в браузере.

**Linux и macOS:** `./start.sh` — то же самое.

Вручную, если хочется по шагам:

```bash
npm install
npm run seed     # необязательно: демо-страницы, пароль у всех vonline2010
npm start        # http://localhost:8080
```

При запуске в консоли печатаются оба адреса: `localhost` для себя и адрес в локальной
сети — его и раздавайте друзьям.

Демо-аккаунты после `npm run seed`: `pavel`, `ivan`, `olga`, `max`.
Свои страницы заводятся обычной регистрацией на `/register`.

Для разработки: `npm run dev` (перезапуск при изменении файлов).

## Запуск в локальной сети

Сервер по умолчанию слушает `0.0.0.0:8080`, то есть уже доступен со всех машин сети.
На компьютере-«сервере» узнайте адрес (`ip a` или `ipconfig`) и раздайте друзьям ссылку
вида `http://192.168.1.50:8080`.

Чтобы вместо адреса был человеческий домен, пропишите на каждой машине в hosts:

```
192.168.1.50   vonline.local
```

(`/etc/hosts` в Linux и macOS, `C:\Windows\System32\drivers\etc\hosts` в Windows.)

## Статическая версия для сети RetroCore

Кроме серверной, есть версия из обычных файлов — HTML, CSS и JavaScript, без
серверного кода. Её можно загрузить в сеть RetroCore как обычный сайт
(«Вариант А»: сайт, загруженный в сеть).

```bash
npm run static      # соберёт dist/ и vonline-site.zip
```

В архиве `index.html` лежит в корне, все ссылки внутри относительные,
своя страница ошибки — `404.html`. Заливается целиком.

Что там работает: стена с записями и вложениями (фото, видео, музыка,
документы), «мне нравится», комментарии, закрепление и правка, альбомы с
просмотром и листанием, видео, музыка, документы, группы со своей стеной,
заметки себе, поиск по странице, все пять оформлений и свои цвета неоновой темы,
мобильная раскладка. Оформление берётся из тех же файлов `public/css/`, что и у
серверной версии, — это ровно тот же вид.

Чего там нет и быть не может: друзей, личных сообщений между людьми, живой ленты
и уведомлений. Для этого нужен сервер — им занимается основная версия.

### Как это устроено

Сервера нет, поэтому данные живут в браузере хозяина страницы: тексты в
localStorage, файлы в IndexedDB. Опубликованное состояние лежит в самом архиве —
`data/site.json` плюс папка `uploads/`, и именно его видят гости.

Круг такой: хозяин правит страницу у себя → в «Моих Настройках» жмёт
**«Собрать архив сайта»** → браузер сам складывает готовый ZIP (все файлы сайта
плюс свежие данные и загруженные картинки) → этот архив заливается в сеть вместо
старого. После этого страница такая для всех.

### Что даёт сеть

Загруженный в сеть сайт подключает её скрипт `/connect.js` и знает, кто его
открыл: страница здоровается по имени, раздел «Люди сети» показывает участников
со ссылками на профили, а в карточку проекта в профиле хозяина уходят показатели
(сколько записей, фотографий, музыки, групп).

Хозяин узнаётся по имени в сети — оно задаётся в настройках, в поле
«Имя в сети RetroCore». Совпало с тем, кто открыл страницу, — включается правка.
На чужом компьютере или вне сети правку можно включить ссылкой в самом низу.

## Вход через сеть RetroCore

Если сайт живёт внутри сети RetroCore, отдельные логины не нужны: участник жмёт
**«Войти через RetroCore»**, и страница в ВОнлайне заводится сама по его аккаунту
сети. Это «Вариант Б» из инструкции сети — отдельный проект со своим сервером.

Как включить:

1. В сети: **Панель сервера → Приложения → Новое приложение**. Название, значок,
   адрес проекта. В поле адреса возврата впишите
   `http://ВАШ-АДРЕС:8080/connect/callback` — тот самый адрес, по которому сайт
   видят люди (не `localhost`). Он должен совпадать символ в символ.
2. Скопируйте `client_id` и `client_secret` (секрет показывают один раз).
3. Заведите рядом с проектом файл `.env`:

```
RC_BASE=http://88.87.70.78:8080
RC_CLIENT_ID=ваш-client_id
RC_CLIENT_SECRET=rcs_ваш-секрет
RC_REDIRECT_URI=http://192.168.1.50:8080/connect/callback
```

4. Перезапустите сайт. На странице входа появится кнопка.

Что происходит при первом входе: заводится страница, логин берётся из имени в сети,
имя и статус — из профиля сети. Дальше это обычная страница ВОнлайне: имя, анкета и
всё остальное правятся в настройках и из сети больше не перезаписываются. Пока своя
фотография не загружена, показывается аватарка из RetroCore.

Пароля у такой страницы нет вовсе — в базе лежит случайный хеш, подобрать который
нельзя. Если хочется входить ещё и обычным способом, пароль заводится в
«Мои Настройки» → «Свой пароль».

Без этих настроек кнопки просто нет, сайт работает на логинах с паролями как раньше.

### Проверить вход, не имея доступа к сети

В комплекте есть игрушечный RetroCore — он повторяет ровно то, что описано
в инструкции сети:

```bash
npm run mock:retrocore          # поднимется на http://127.0.0.1:8099
```

и `.env` для проверки:

```
RC_BASE=http://127.0.0.1:8099
RC_CLIENT_ID=demo
RC_CLIENT_SECRET=rcs_demo
RC_REDIRECT_URI=http://127.0.0.1:8080/connect/callback
```

### Видео: обложки и длительность

Видеозаписи принимаются и играют без дополнительных программ. Если на сервере есть
**ffmpeg** (`apt install ffmpeg`), при загрузке дополнительно снимается кадр-обложка
и определяется длительность — для видео, аудио и голосовых сообщений. Без ffmpeg всё
работает, просто без обложек. При старте сервер пишет в консоль, нашёл он ffmpeg или нет.

### Голосовые сообщения

Записываются браузером через микрофон. Браузеры отдают микрофон только на `localhost`
или по HTTPS, поэтому для записи с других машин поставьте сайт за nginx с самоподписанным
сертификатом. Всё остальное по обычному http работает как есть.

### Через Docker

```bash
docker compose up -d --build
```

Данные и загрузки лежат в томах `vo-data` и `vo-uploads` и переживают пересборку.

### Очистка перед запуском для людей

```bash
npm run reset -- --yes     # сотрёт все страницы, записи и загрузки
```

### Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `8080` | порт |
| `HOST` | `0.0.0.0` | интерфейс |
| `VO_DATA_DIR` | `./data` | база SQLite и секрет сессий |
| `VO_UPLOAD_DIR` | `./uploads` | фотографии, аватары, видео, аудио, документы |
| `VO_SECRET` | генерируется | секрет подписи сессий |
| `RC_BASE` | `http://88.87.70.78:8080` | адрес сети RetroCore |
| `RC_CLIENT_ID` | — | идентификатор приложения из панели сети |
| `RC_CLIENT_SECRET` | — | секрет приложения, наружу не отдаётся |
| `RC_REDIRECT_URI` | — | адрес возврата, слово в слово как в панели сети |

Переменные читаются из окружения или из файла `.env` рядом с проектом.

## Резервная копия

Всё состояние — это две папки:

```bash
cp -r data uploads /куда-нибудь/backup-$(date +%F)
```

## Ограничения на файлы

| Тип | Предел | Форматы |
|---|---|---|
| Изображения | 12 МБ | JPEG, PNG, GIF, WebP |
| Видео | 256 МБ | MP4, WebM |
| Аудио | 30 МБ | MP3, OGG, WAV, FLAC, M4A, WebM |
| Голосовое | 10 МБ | то, что пишет браузер (обычно WebM/Opus) |
| Документы | 50 МБ | PDF, ZIP, RAR, 7z, gzip, текстовые файлы |

Тип определяется **по содержимому файла**, а не по тому, что сказал браузер. Поэтому SVG
и исполняемые файлы не принимаются: SVG — это документ со скриптами внутри.

## Как устроено

```
src/
  server.js          сборка приложения, статика, сессии, заголовки, обработка ошибок
  db.js              схема SQLite и миграции
  ws.js              WebSocket-хаб: сообщения, «печатает», статус в сети
  lib/
    auth.js          scrypt-хеши паролей, текущий пользователь, счётчики
    security.js      csrf-токены, ограничение частоты, безопасные редиректы, заголовки
    media.js         определение типа по сигнатуре, превью, ffmpeg, размеры
    attach.js        приём вложений и раскладка их по photos/videos/audios/docs
    publish.js       создание, правка и удаление записей
    notify.js        уведомления и упоминания
    models.js        запросы к базе: люди, дружбы, приватность, стена, беседы
    session-store.js хранилище сессий в той же SQLite
    util.js          даты, склонения, экранирование, разбор упоминаний
    view.js          пути к файлам и форма-действие для шаблонов
  routes/            auth, profile, settings, friends, wall, im, photos, video,
                     audio, docs, groups, notifications, misc
views/               шаблоны EJS
public/css/vo.css    всё оформление
public/js/vo.js      лайки, комментарии, живые события, запись голоса
scripts/seed.js      демо-данные
```

Стек: Node.js 20+ и Express 5, серверные шаблоны EJS, SQLite (better-sqlite3),
sharp для картинок, ws для живых событий. Внешних сервисов нет.

Схема обновляется сама при запуске: старые базы первой версии переезжают на новую
модель (личные сообщения превращаются в беседы, одиночные вложения — в общий список).

## Про безопасность

Что сделано:

- пароли — scrypt с солью, минимум 8 символов, простые пароли отклоняются;
- сессии httpOnly, `SameSite=lax`, хранятся в базе, пересоздаются при входе;
- **csrf-токен на каждом изменяющем действии** — поэтому «удалить» и «добавить в друзья»
  оформлены формами, а не ссылками;
- ограничение частоты: вход, регистрация, записи, комментарии, сообщения, загрузки;
- весь пользовательский текст экранируется, имена файлов чистятся от путей и разметки;
- тип файла определяется по сигнатуре, картинки пережимаются через sharp;
- загрузки отдаются с `nosniff`, песочницей в CSP и без разбора типа браузером,
  документы — только через отдельный адрес и всегда вложением;
- заголовки: CSP без `unsafe-inline` для скриптов, `X-Frame-Options`, `Referrer-Policy`,
  `Permissions-Policy`;
- редиректы только на внутренние адреса, `Origin` проверяется при подключении сокета;
- смена пароля завершает остальные сеансы;
- вход через RetroCore: одноразовый `state` в сессии против подмены возврата,
  код меняется на участника только с сервера, секрет приложения наружу не уходит,
  ссылки и аватарки из ответа принимаются только с адреса самой сети.

Чего нет: HTTPS (ставьте nginx, если нужно), капчи, модерации, антивируса для загрузок.
Сайт рассчитан на доверенную локальную сеть; выставлять его в интернет как есть не стоит.
