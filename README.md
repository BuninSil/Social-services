# ВОнлайне (ВО)

Социальная сеть для локальной сети, сделанная по образцу социальных сетей конца нулевых:
фиксированная ширина 940px, Tahoma 11px, серый фон, белые блоки с тонкой рамкой, анкета
таблицей и стена внизу страницы. Никакой адаптивности, никаких SPA — обычные страницы,
которые отдаёт сервер.

## Что умеет

| Раздел | Что внутри |
|---|---|
| Страница | аватар, статус, анкета (день рождения, город, семейное положение, полит. взгляды, интересы, музыка, фильмы, книги, игры, цитаты, о себе), счётчики |
| Друзья | заявки входящие и исходящие, подтверждение, удаление, общие друзья |
| Стена | записи себе и друзьям, фото во вложении, «Мне нравится», комментарии, удаление |
| Сообщения | список диалогов, история, непрочитанные, мгновенная доставка по WebSocket |
| Фотографии | альбомы, загрузка пачкой, просмотр с листанием, лайки и комментарии к фото |
| Аудиозаписи | загрузка своих файлов, встроенный плеер |
| Группы | создание, аватар, участники, стена группы, права создателя |
| Новости | лента записей друзей и групп |
| Поиск | поиск людей по имени, фамилии и логину |
| Настройки | вся анкета, аватар, смена пароля, кто может писать на стену |

Мелочи в духе эпохи: даты вида «сегодня в 14:03» и «12 мар в 9:15», правильные склонения
(«3 друга», «5 друзей»), «был на сайте» / «была на сайте», Ctrl+Enter отправляет форму.

## Быстрый старт

```bash
npm install
npm run seed     # необязательно: демо-страницы, пароль у всех 123456
npm start        # http://localhost:8080
```

Демо-аккаунты после `npm run seed`: `pavel`, `ivan`, `olga`, `max` — пароль `123456`.
Свои страницы заводятся через обычную регистрацию на `/register`.

Для разработки: `npm run dev` (перезапуск при изменении файлов).

## Запуск в локальной сети

Сервер по умолчанию слушает `0.0.0.0:8080`, то есть уже доступен со всех машин в сети.
На компьютере-«сервере» узнайте адрес (`ip a` или `ipconfig`) и раздайте друзьям ссылку
вида `http://192.168.1.50:8080`.

Чтобы вместо адреса был человеческий домен, пропишите на каждой машине в hosts:

```
192.168.1.50   vonline.local
```

(`/etc/hosts` в Linux и macOS, `C:\Windows\System32\drivers\etc\hosts` в Windows.)

### Через Docker

```bash
docker compose up -d --build
```

Данные и загрузки лежат в томах `vo-data` и `vo-uploads`, так что переживают пересборку.

### Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `8080` | порт |
| `HOST` | `0.0.0.0` | интерфейс |
| `VO_DATA_DIR` | `./data` | база SQLite и секрет сессий |
| `VO_UPLOAD_DIR` | `./uploads` | фотографии, аватары, аудио |
| `VO_SECRET` | генерируется | секрет подписи сессий |

## Резервная копия

Всё состояние — это две папки. Копируются на ходу:

```bash
cp -r data uploads /куда-нибудь/backup-$(date +%F)
```

## Как устроено

```
src/
  server.js          сборка приложения, статика, сессии, обработчики ошибок
  db.js              схема SQLite и подключение
  ws.js              WebSocket-хаб для живых сообщений
  lib/
    auth.js          scrypt-хеши паролей, текущий пользователь, счётчики
    models.js        запросы к базе: люди, дружбы, стена, лайки, лента
    session-store.js хранилище сессий в той же SQLite
    upload.js        приём файлов и превью через sharp
    util.js          даты, склонения, экранирование текста
    view.js          пути к аватарам и превью
  routes/            auth, profile, settings, friends, wall, im, photos, audio, groups, misc
views/               шаблоны EJS, вёрстка страниц
public/css/vo.css    всё оформление
public/js/vo.js      лайки, комментарии, живые сообщения
scripts/seed.js      демо-данные
```

Стек: Node.js + Express 5, серверные шаблоны EJS, SQLite (better-sqlite3), sharp для картинок,
ws для сообщений. Никаких внешних сервисов и сборщиков — `npm install && npm start`.

## Про безопасность

Сайт рассчитан на доверенную локальную сеть. Что сделано: пароли хранятся как scrypt-хеши,
сессии httpOnly и лежат в базе, весь пользовательский текст экранируется, файлы принимаются
только по mime-типу и с ограничением размера, картинки пережимаются через sharp.

Чего нет и не предполагается: HTTPS, защиты от подбора паролей, CSRF-токенов, модерации.
Выставлять это в интернет как есть не стоит.
