# ВОнлайне — сайт на PHP, без SQL

Социальная сеть в духе ВКонтакте конца нулевых. Серверный код и база лежат
прямо в папке сайта: никакой внешней СУБД, никакого SQL, ничего собирать не надо.
Залил папку на хостинг — сайт работает.

## Что нужно от хостинга

* PHP 8.1 или новее (проверено на 8.4);
* расширения: `openssl` (шифрование базы), `mbstring`, `json`, `fileinfo`;
* `gd` — по желанию, для уменьшения больших фотографий. Без него картинки
  сохраняются как есть;
* право на запись в папки `data/` и `uploads/`.

Базы данных, Node, композера и прочего — не нужно.

## Установка

1. Залейте содержимое этой папки в корень сайта (или в подпапку — адреса
   всё равно соберутся правильно).
2. Дайте права на запись:

   ```
   chmod 700 data uploads
   ```

   На большинстве панелей достаточно выставить 755, если сайт работает
   от вашего пользователя.
3. Откройте сайт в браузере и зарегистрируйтесь — первая страница станет вашей.
   Если регистрацию решите закрыть, страницу можно завести из консоли:

   ```
   php tools/account.php vladislav "Владислав Бунин" ваш-пароль
   ```

   Той же командой меняется пароль у существующей страницы.
4. Когда все свои зарегистрировались — закройте регистрацию в `app/config.php`:
   `'open_register' => false`.

### Если нет mod_rewrite

`.htaccess` в комплекте, Apache и LiteSpeed подхватят его сами. На nginx
добавьте в конфиг сайта:

```
location / { try_files $uri $uri/ /index.php?p=$uri&$args; }
location ~ ^/(data|app|tools)/ { deny all; }
location /uploads/ { add_header X-Content-Type-Options nosniff; }
```

Если переписывать адреса нечем вообще — сайт откроется и так, по
`index.php?p=/feed`: такой запасной разбор адреса встроен.

## Настройки

Единственный файл, который нужно править — `app/config.php`:

| Ключ | Что делает |
| --- | --- |
| `retrocore` | связь с сетью RetroCore: `false` — сайт полностью сам по себе |
| `retrocore_base`, `retrocore_client_id`, `retrocore_client_secret`, `retrocore_redirect_uri` | данные приложения из панели сети |
| `title` | название в шапке и заголовке вкладки |
| `open_register` | открыта ли регистрация |
| `theme` | оформление по умолчанию: `vo`, `dark`, `neon`, `fresh`, `modern` |
| `limit_image`, `limit_audio`, `limit_video`, `limit_doc` | пределы на размер файла, мегабайты |
| `resize_images` | уменьшать ли большие фотографии (нужен `gd`) |

## Где что лежит

```
index.php       разбор адреса и список страниц
app/            серверный код: база, модели, страницы, шаблоны
data/           база — зашифрованные JSON-файлы, ключ и сеансы
uploads/        всё загруженное: фото, музыка, видео, документы, аватарки
assets/         оформление и клиентский скрипт
tools/          консольные мелочи
```

### База

Каждая коллекция — отдельный файл в `data/`, например `users.json`.
Внутри не открытый JSON, а конверт:

```json
{"v":1,"alg":"aes-256-gcm","iv":"…","tag":"…","data":"…"}
```

Ключ — `data/secret.key`, 32 случайных байта, создаётся сам при первом запуске.
**Потеряете ключ — данные не прочитает никто, включая вас.** Запись идёт
через временный файл с переименованием, рядом остаётся `.bak`, изменения
берут блокировку — выдернутое питание базу не портит.

Если `openssl` на хостинге нет, файлы пишутся в base64 без шифрования —
сайт работает, но данные защищены только правами на папку.

### Резервная копия

Копируйте две папки целиком: `data/` и `uploads/`. Больше ничего сохранять
не нужно, восстановление — распаковать их обратно.

## Связь с сетью RetroCore

По умолчанию выключена, сайт живёт сам по себе.

Чтобы включить: в панели сети (Панель сервера → Приложения) заведите
приложение, адрес возврата укажите `https://ваш-сайт/connect/callback`
символ в символ, а в `app/config.php` поставьте `'retrocore' => true` и
впишите выданные `client_id` и `client_secret`.

Из сети берутся **только** люди: имя, логин, аватарка, статус и список
участников на странице «Люди сети». Всё остальное — записи, комментарии,
переписка, фотографии, музыка, видео, документы, группы — как и раньше
хранится в папках этого сайта.

Вход по паролю при этом никуда не девается: у кого он есть, заходят по-старому.
У страницы, заведённой через сеть, пароля нет — его можно задать в настройках.

## Безопасность

* пароли — `password_hash()`, в базе только хеш;
* на каждую форму свой одноразовый токен, чужой POST не пройдёт;
* тип загруженного файла определяется по содержимому, а не по расширению;
  `.php`, `.html` и `.svg` внутрь `uploads/` не попадают;
* в `uploads/` выключено выполнение скриптов, документы отдаются только
  вложением через PHP;
* `data/`, `app/` и `tools/` закрыты от прямого обращения;
* заголовки CSP, `nosniff`, `X-Frame-Options`;
* частота входов, загрузок и смен пароля ограничена.

## Проверить локально

```
php -S 127.0.0.1:8100 router.php
```

`router.php` нужен только серверу для разработки, на хостинге он не участвует.
